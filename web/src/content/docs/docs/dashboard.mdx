Open your learning history, project memory, saved pages and settings in a local browser:

```bash
eklavya dashboard
```

The dashboard lives at `http://127.0.0.1:41729` and keeps running in the background, so the command opens your browser and returns. Use `--no-open` to print the URL without opening a browser.

## Keeping it running

Each session start checks the dashboard and starts it if nothing is answering, so it comes back after a crash or a restart of your computer. When a session starts it, the greeting says so:

```text
Dashboard http://127.0.0.1:41729 started in the background · off: eklavya config set dashboard_autostart false
```

After an update, the next session replaces a dashboard running an older version. A dashboard started from a newer version is left alone, and so is one serving a different database (`EKLAVYA_DB`) or another program on the port.

```bash
eklavya dashboard status   # version, process id and database of the running copy
eklavya dashboard stop     # stop it; the next session starts it again
```

To keep it off, set [`dashboard_autostart`](/docs/configuration/#every-key) to `false` (global only). `eklavya dashboard` then runs in the foreground as before, and **Ctrl+C** stops it. With `--port <n>` it always runs in the foreground on that port; a busy requested port returns an error. Without `--port`, a foreground dashboard whose default port is busy falls back to an available one.

The background copy writes errors to `~/.eklavya/dashboard.log`, cleared each time it starts.

`/eklavya:progress` gives a short summary in chat. The dashboard is where you inspect full histories and follow links between a concept, its questions, the session and the memory behind it.

## Switching workflow

Use the caret beside the workflow name to choose **Learning**, **Memory**, **Artifacts** or **Settings**. Clicking the name or Eklavya wordmark returns to that workflow's Dashboard.

Project and theme choices survive a workflow switch. Page-specific filters do not. The address records the workflow, page, filters and project, so bookmarks and Back/Forward return to the same view. A new-style link without `?project=` means all projects.

## The sidebars

| Learning | Memory | Artifacts | Settings |
| --- | --- | --- | --- |
| Dashboard | Dashboard | Dashboard | Overview |
| Concepts, Review | Timeline, Sessions, Projects | Projects | User, Project |
| Sessions, Projects, Domains | Reuse, Health | | |

Groups can be collapsed and are remembered per workflow. At 900 px or narrower, navigation moves into a menu drawer. Keyboard navigation supports Tab and Enter; the workflow picker also supports arrows and Escape. Escape or clicking outside closes the drawer.

## Reading a page

Every page follows the same order, so the answer comes before the detail:

1. **The title and one line of counts.** For example, `85 concepts asked of 334 · 96 answers · since 26 Aug`. A count that needs attention, such as pending evidence, is a link.
2. **How this works**, folded. Open it for the arithmetic behind the page: mastery thresholds, decay, how savings are estimated.
3. **The one next step**, when there is one: concepts due for review (questions you declined, did not know or got wrong), or a stalled memory job.
4. **The lists**, one line per item. Open a line, or its page, for the rest.
5. **Secondary sections, folded.** The practice calendar, grade history, capture settings and similar detail sit in closed sections whose summary line still shows a count or verdict. Open one with a click, Enter or Space.

The dashboard remembers which sections you opened or closed, in this browser only.

## Learning

| Page | What you can inspect |
| --- | --- |
| Dashboard (`#/learning/dashboard`) | Accuracy, mastery, due reviews and streak; recorded versus assessed concepts in the counts line; 30 days of answers; the weakest five concepts and recent sessions. Where you stand and the practice calendar are folded. |
| Concepts (`#/learning/concepts`) | Search, sort and filter the graph by domain or state: due, learning, mastered or unseen. |
| Review (`#/learning/review`) | Due reviews, upcoming reviews with a 14-day forecast, and skipped questions. Due and upcoming list only concepts whose latest answer was declined, blank or wrong; a correct answer is never owed. Tabs use `/upcoming` and `/skipped`. |
| Sessions (`#/learning/sessions`) | Sessions that logged concepts or asked questions. Memory-only sessions are listed in Memory. |
| Projects (`#/learning/projects`) | One line per project: level, accuracy and last activity. Open it for logged and assessed concepts, promotion conditions and 30 days of answers. Projects with logged work but no answers say “not assessed”. |
| Domains (`#/learning/domains`) | Concept coverage and the spread of question tiers. |

## Memory pages

| Page | What you can inspect |
| --- | --- |
| Dashboard (`#/memory/dashboard`) | Memory counts, a two-line pipeline status (estimated reuse and health, each linking to its page), recent observations and sessions. |
| Timeline (`#/memory/timeline`) | Entries by day, one line each; open a line for its summary and a link to the full entry. Filter by type, tag or date, and search titles, narratives, facts and file paths. |
| Sessions (`#/memory/sessions`) | Sessions with evidence or observations, including pending evidence and questions from the same session. |
| Projects (`#/memory/projects`) | Every project with captured memory, including evidence not yet summarised. |
| Reuse (`#/memory/reuse`) | A receipt for each recall and its context-volume arithmetic. |
| Health (`#/memory/health`) | Capture heartbeat, processing queue, stalled jobs and provider configuration. |

Type filters use paths such as `#/memory/timeline/bugfix`; tag and date filters use `?tag=auth&from=2026-09-01&to=2026-09-23`. The date menu's Today, Last 7 days and Last 30 days set only `from`; Custom range shows both date boxes.

## Artifacts

Artifacts are HTML pages saved under `~/.eklavya/artifacts/<project>/`: requested explanations and background explainers created when [`explain_on_wrong`](/docs/configuration/#every-key) is enabled.

| Page | What you can inspect |
| --- | --- |
| Dashboard (`#/artifacts/dashboard`) | Pages grouped by project, newest first. Search title, description, concept and project; filter with `/explainer` or `/artifact`. |
| Projects (`#/artifacts/projects`) | Page and explainer counts and the latest page in each project. |

An explainer's concept links to its Learning page. Page titles open the saved HTML in a new tab. The file list is reread on refresh, so adding or deleting a file updates the library. A project with artifacts but no other recorded activity appears here but cannot be selected as a global project scope.

Pages served by the dashboard are sandboxed: their inline scripts and downloads work, but they cannot read dashboard history. Only files under the artifacts directory are served. The template's Google Fonts requests are allowed; offline it uses system fonts. The Eklavya link in the header and footer opens the website in a normal tab. Opening the same file directly does not add the dashboard sandbox.

## Settings

Settings changes the same two files as [`eklavya config set`](/docs/cli/#settings-and-browsing): your user settings in `~/.eklavya/config.json`, and one project's settings in `~/.eklavya/projects/<checkout>/config.json`. Both interfaces use one write path, so they accept and refuse the same values.

| Page | What you can do |
| --- | --- |
| Overview (`#/settings/dashboard`) | See how many settings each file sets, and which settings the selected project changes from yours. |
| User (`#/settings/user`) | Change a setting everywhere. **Reset to default** removes it from your file. |
| Project (`#/settings/project?project=<checkout>`) | Change a setting for one project. Each row says whether its value is set for this project, inherited from your user settings, or the default. **Inherit** removes the project's value so your user setting applies again. Without a project selected, it lists the projects you can configure. |

A control saves when you change it; a text or number box saves when you leave it or press Enter. The row reports **saved** or **inherited**. Each field states what it accepts, and a value outside that is refused under the field before anything is sent, keeping what you typed; the server checks again with the [same rules](/docs/configuration/#what-each-setting-accepts) and reports a refusal, such as `focus: learn` with no topic, in the same place. `auto_update` and `telemetry` apply to the whole machine, so a project page shows them read-only with a link to User. Providers, notifications and sync send work off the machine or run a command, so the pages list them under **Changed from the terminal** with their current value instead of offering a control.

Only projects with a git checkout on this machine can be configured. The footer's dial line is read when the page loads, so it updates on the next refresh.

## Opening one thing

| Detail page | Contains |
| --- | --- |
| Concept (`#/learning/concept/<slug>`) | Score and decay, review schedule, and every recorded question as one line that opens to its options and feedback. Grade history, logged context and connected concepts are folded. |
| Session (`#/learning/session/<id>` or `#/memory/session/<id>`) | Logged work and the questions asked, then folded sections for review concepts, observations and proposed concepts. Both routes show the same session with the originating workflow's sidebar. |
| Domain (`#/learning/domain/<name>`) | Concepts ordered by weakness, with mastery and learning state. |
| Observation (`#/memory/entry/<id>`) | Narrative, facts, files, tags, summariser, confidence, concept candidates, reuse receipts and expandable raw evidence. Corrections link to the replacement. |

Invalid routes show an error with links back to the Dashboards. Rows and relevant count tiles are links you can reach with the keyboard.

## Reading the timeline

The timeline is an audit trail. Superseded and soft-deleted entries remain labelled and struck through there, although retrieval excludes them. Search treats `%`, `_` and `\` as literal characters.

The timeline groups entries under a heading for each local day and says when a stretch of days has nothing. When a session's summary is on the same page as its observations, they fold under one session line; open it to see them. Grouping is per page, so a session whose summary is on another page shows its observations as ordinary lines.

The Memory Dashboard shows observations, sessions, pending evidence and reuse as tiles, and the distilled, indexed, reused, delivered and assessed totals on one line under its title. The timeline shows observations, sessions and pending evidence on one line.

| Count | Meaning |
| --- | --- |
| Observations | Live entries, excluding superseded and deleted ones; also reports how many are indexed as vectors. |
| Pending | Captured raw events not yet summarised into an observation, out of all evidence events. |
| Sessions | Sessions that captured evidence or wrote observations. |
| Reused | Entries selected for recall and those confirmed as delivered. |
| Assessed | Concepts proposed from evidence that you actually answered a question about. |

With a project selected, observations, evidence and sessions are scoped to it. Indexing, reuse, delivery and assessment totals that remain database-wide are labelled “all projects”. Captured or recalled material does not count as understanding.

## Reuse: what `B` and `D` mean

A recall receipt compares **base (`B`)**, the raw evidence behind the entries, with **delivered (`D`)**, the context actually supplied, including later detail fetches. Both use the same four-characters-per-token estimate. Estimated reduction is `(B − D) / B`.

Receipts can be `confirmed`, `unknown` or `prepared`. Only confirmed delivery contributes to headline savings. Unconfirmed receipts stay visible without a saving claim. Longer summaries can produce overhead, which is reported rather than hidden.

This measures estimated context volume compared with raw evidence, not your bill, API cache hits or model spend. See [Memory](/docs/memory/#what-the-savings-percentage-measures).

## Health

Use the health page to locate a gap between capture, processing, indexing, retrieval and delivery:

| Signal | Meaning or next step |
| --- | --- |
| Last capture | Old despite recent work: inspect capture and installation. |
| Queued, paused or failed jobs | Check the oldest job and error class. Transient failures retry. Auth, quota and missing-command problems pause the queue: it rechecks itself at most every 30 minutes, or run `eklavya memory process` after fixing the cause. |
| Dropped events | Evidence could not be retained while the database was unavailable. `eklavya memory replay` can recover eligible transcript history. |
| Provider settings | Shows what is configured. Only the observer currently runs a model; an embeddings setting does not change the local search implementation. |

Provider error classes are shown without raw messages, which can quote captured content. `eklavya memory status` gives the terminal view of the same health information.

## Projects, scope, ground and paging

The project selector includes projects with attempts, logged concepts, evidence, observations, reuse receipts or earned levels. Folder names identify projects; duplicate names include a parent folder. Worktrees resolve to their main checkout when that relationship is known. Missing checkouts remain listed as “checkout gone”. **No repository** means work outside git; **Unattributed** means older rows without a project.

Selecting a project scopes lists and activity, but concept mastery and review dates remain shared. The selected project is saved in the URL. The ink/paper theme is remembered in your browser.

Most lists show 20 rows per page; the memory timeline shows 25, and a concept's question history shows ten, one line each.

## While you leave it open

The dashboard is a snapshot. Once a minute, while the tab is visible, it checks for new activity and offers a **refresh** notice. It does not redraw automatically while you are reading. Refresh preserves your route and filters; stopping the server leaves the loaded view visible.

## What it is, underneath

The dashboard reads the local database and binds to `127.0.0.1`. It accepts only `GET` and `HEAD`, except a settings change, validates loopback request addresses, escapes stored content and refuses framing by other pages. Dashboard views load no external fonts or other remote resources; artifact pages have the font exception described above.

Its read-only JSON endpoints serve summary state (`/api/state`), project inventory (`/api/projects`), paged memory (`/api/memory`), entry detail (`/api/memory/entry`), memory sessions (`/api/memory/sessions`) and settings (`/api/settings`). The one write is `POST /api/settings`, which changes one setting. It needs a loopback `Origin`, a JSON body of at most 256 KB and a random token the server puts in the page each time it starts, so another site open in your browser cannot change your settings. It never edits learning or memory data.
