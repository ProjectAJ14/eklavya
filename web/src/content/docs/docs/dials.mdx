Choose what Eklavya teaches and how often it asks. These settings are independent; memory has its own switch.

| Setting | Default | Other choices |
| --- | --- | --- |
| `quiz.enabled` | `true`: offer questions | `false`: no questions or gate; memory can continue. |
| `quiz.enforced` | `false`: commits are unrestricted | `true`: require passing answers before committing. |
| `focus` | `concept`: the idea behind the code | `project`: this codebase; `learn`: a chosen topic. |
| `cadence` | `interleaved`: one question during work | `end`: questions when the task finishes. |
| `difficulty` | `auto`: earn a level per project | Pin `easy`, `medium` or `hard`. |
| `memory.enabled` | `true`: record and recall work | `false`: learning continues without memory capture or recall. |

### `quiz` — whether it asks, and whether it insists

Questions are optional by default. With `quiz.enforced: true`, enough answers must pass before `git commit` succeeds. This applies automatically to commits Claude Code makes; commits from a terminal require the separate [git hook](/docs/commit-gate/).

Automatic questions only come in sessions that change code. With the default `quiz.only_on_changes: true`, Eklavya asks nothing until the session edits a file inside a git repository through Claude's edit tools (a sibling worktree counts; notes, plans and ignored files do not), or the git working tree the session started in differs from how it looked at the start. Questions cover the work logged since you last came back after more than an hour away, newest first, so a session left open overnight is not asked about yesterday, and a long task stays covered while you keep working. Research and read-only sessions stay quiet, and `/eklavya:quiz` still works in them. Set it to `false` to be asked about any logged work.

Setting `quiz.enabled: false` disables questions and enforcement. It does not stop memory; when memory is on, the session banner reports “memory on · questions off”. To stop both halves, also set `memory.enabled: false`.

For temporary quiet, use `/eklavya:mode off --session`. This silences questions and the banner for this session without changing a file, but **keeps an enforced commit gate active**. See [session scope](/docs/configuration/#turning-it-off-for-one-session).

### `focus` — what it teaches

| Value | Questions are about | Example |
| --- | --- | --- |
| `concept` | Transferable ideas behind the work | Why an index changes query cost. |
| `project` | Files and decisions in this codebase | Why this query uses the new index. |
| `learn` | A named topic, prerequisites first | Learn database indexing over future sessions. |

`learn` requires `focus_topic`; without it, no topic quiz is planned. An unmet enforced gate takes priority and asks about the current work first, even with `learn` focus. The chosen topic resumes after the gate passes.

### `cadence` — when it asks

**Interleaved** offers one question when concepts are logged, then at eligible shell commands, edits or completed turns. Offered questions are at least `min_minutes_between_checkpoints` apart (four minutes by default).

**End** waits until a task finishes, then asks the remaining budget one question at a time. `min_minutes_between_quizzes` spaces these offered quizzes (20 minutes by default).

Automatic checkpoints and the final sweep share `max_questions_per_task`: four questions across the session by default. Interleaving moves that budget earlier without adding automatic questions. Enforcement removes the planner's one-question cap and normal quiz cooldown, but automatic hooks still stop when their session budget is spent.

Each explicit `/eklavya:quiz` round can plan up to `max_questions_per_task` eligible questions even after that automatic budget is exhausted. Use it to continue learning or retry a taught miss when an enforced gate remains blocked.

Unasked work can return in a later session in the same project, after current work is covered. Raise checkpoint spacing if you want fewer interruptions; choose `end` if you want none during the task.

### `difficulty` — how hard it may get

With `auto`, each project starts at `easy` and can earn promotion. Pinning a value stops progression. A level sets the allowed tier range, not the tier of every question: `easy` allows 1–2, `medium` 2–4, and `hard` 3–5. See [Levels and tiers](/docs/levels-and-tiers/).

### Changing a dial

```text title="In Claude Code"
/eklavya:mode
/eklavya:mode project
/eklavya:mode off --session
/eklavya:level medium
```

```bash title="In a terminal"
eklavya config set quiz.enforced true --project
eklavya config set quiz.enabled false
eklavya config set focus learn --topic caching
eklavya config set cadence end
```

Without `--project`, CLI changes are global. Personal project settings override global values and live under `~/.eklavya/projects/`, outside your repository. Worktrees share the main checkout's settings; teammates keep their own.

Older `mode: ambient|enforced|off` files still work. New files should use `quiz`. For every key and default, see [Configuration](/docs/configuration/).
