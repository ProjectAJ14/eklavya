For example, ask Claude to “Add JWT authentication to the Express API.” As it
implements the change, it logs concepts tied to the actual code. With the
default `interleaved` cadence, that logging call can trigger a question. Later
edits and shell commands provide further checkpoints, paced by a four-minute
interval. Task completion can bring one more question, subject to the same
pacing and session budget. It comes after Claude's answer, and Claude then
repeats a short version of the answer under “Back to your task:”.

For a change that spans several files, [`delegate_work`](/docs/configuration/#every-key)
(on by default) has Claude hand the building to background agents; if Claude
changes a second file itself, with an edit tool or a shell command, Eklavya
reminds it once. Under the
default `interleaved` cadence, questions then come one at a time while they
work, and the task answer arrives last.

Answers are graded from 0 to 5. Concepts you struggle with return sooner;
successful reviews are spaced further apart. A new session also shows a short
settings and progress banner. `quiet: true` hides that banner without disabling
questions or memory.


Nothing is asked until the session changes a file: through Claude's edit tools in any git repository, including a sibling worktree, or in the git working tree it started in. A session spent reading, researching or answering questions gets no questions, including one started in a folder that holds repositories but is not one. Enforced quizzing and `/eklavya:quiz` are not held back.

The default budget is **four questions per session**, even though the setting
is named `max_questions_per_task`. Explicit practice and enforced gate retries
can behave differently; see [The dials](/docs/dials/) and
[The commit gate](/docs/commit-gate/).

Concepts the budget does not reach are dropped once the session is over;
Eklavya does not keep a pile of questions you were never shown. A question you
decline, do not know or get wrong is scheduled for review a day later, and the
next quiz in that project asks it again after that session's own work.

## A checkpoint example

```text
Why is httpOnly set on the refresh cookie here?
```

The question arrives with four choices in Claude's question UI. In a terminal,
it has an **Eklavya** header. In Claude Desktop's Code tab and Cowork, the card
instead begins with `[Eklavya]`.

The terminal status bar shows the current focus, cadence and difficulty:

```text
[EKLAVYA concept · interleaved · easy]
```

The installer configures this status line when possible. If you already have a
custom one, see [`eklavya statusline`](/docs/cli/#eklavya-statusline). Claude
Desktop has no equivalent status bar; use the [dashboard](/docs/dashboard/).

## If you do not know the answer

Choose “I don't know” to get an explanation grounded in the work. Skipping
moves on. Both receive grade 0, but Eklavya records the difference so it can
respond appropriately. A correct multiple-choice answer receives at most
grade 4; [Grading and scheduling](/docs/grading-engine/) explains the scale.

## Make it fit your workflow

Use [The dials](/docs/dials/) to change the pace, topic or difficulty. Use
`/eklavya:quiz` for practice, `/eklavya:progress` for learning progress, and
`/eklavya:memory` for project history. If expected questions never arrive,
start with [Troubleshooting](/docs/troubleshooting/#questions-and-settings).
