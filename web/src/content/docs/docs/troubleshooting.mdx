## Start here

```bash
eklavya doctor
```

Use `npx eklavya doctor` if you did not install the global command. Doctor checks
the runtime, database driver, plugin registration, configuration and optional
dependencies. Follow the repair it reports, then restart Claude Code.

Eklavya's hooks allow your session to continue when they fail, so silence alone
does not prove it is healthy. `eklavya install` repairs a broken installation
without resetting your learning history or settings.

## Installation and updates

| Symptom | Check or repair |
|---|---|
| No session banner | Check `quiet` with `eklavya config get`, then inspect `/plugin` and `eklavya doctor`. A marketplace install may still need `npx eklavya install` to finish the runtime. |
| Plugin registered but not enabled | Enable Eklavya through `/plugin`, or rerun `eklavya install`. |
| Database missing or session says it cannot open the database | Read doctor's `database` and `driver` rows. Confirm Node.js 22+, then run `eklavya install` if the driver is missing or incompatible. |
| It stopped working after upgrading Node.js | The native SQLite driver may need rebuilding for the new Node version. `eklavya install` repairs it. |
| Installer reports invalid JSON | Fix the named file before retrying. Eklavya refuses to overwrite invalid configuration. [Backups](/docs/updates/#installer-safety-and-backups) can restore a previous version. |
| Skill path contains a different skill named `eklavya` | Eklavya preserves your existing skill. Move or rename it yourself, then reinstall. |
| Runtime and plugin versions differ | Run `eklavya update` and restart. Automatic updates normally catch up in a later session; check `auto_update` if they do not. A newer runtime is never downgraded. |
| Automatic update failed | Run `eklavya update` for the full error; inspect `~/.eklavya/update.log`. Missing npm usually means Claude's launch environment has a different `PATH`; a permissions error needs the named files' ownership repaired. |
| Another installation is running | Let the process named by the installer finish, then retry. Do not delete its lock while it is active. |

[Updates and removal](/docs/updates/) explains automatic checks, backups and
runtime catch-up.

## Questions and settings

| Symptom | Check or repair |
|---|---|
| No questions | Check `quiz.enabled`, then run `/eklavya:quiz`. Claude must log concepts tied to the work before Eklavya can ask about them. |
| Questions stopped partway through | The session may have reached its budget, have no eligible concepts, or still be within the checkpoint interval. Ask Claude to log the current task's concepts, then try `/eklavya:quiz`. |
| Questions only arrive at task completion | Check `cadence`. `eklavya config set cadence interleaved` enables mid-task checkpoints; Claude also needs to log concepts while working. |
| Too many interruptions | Increase `min_minutes_between_checkpoints`, decrease `max_questions_per_task`, or choose `cadence: end`. See [The dials](/docs/dials/). |
| Questions are too easy | Run `/eklavya:level` to see this project's progress. Difficulty starts easy in a new project; you can also pin a level through the dials. |
| A global setting seems ignored | `eklavya config get` shows effective settings and the project's override file. Change the override with `--project`. |
| Questions stopped but memory continues | Expected: `quiz.enabled` and `memory.enabled` are separate. `eklavya memory status` shows whether recording is active. |
| A repository's `.eklavya.json` disappeared | It was migrated into your personal project settings. `eklavya config get` shows the new path. |

<details>
<summary>A long session has never logged any concepts</summary>

After about 12 minutes with no logged concepts, Eklavya reminds Claude to log
what the task exercises. It repeats at most every 25 minutes, up to three
times. Resuming or compacting resets the reminder state. `quiz.enabled: false`
disables the reminder; `quiet` does not.

This reminder does not fire after a session has already logged concepts. For
that case, ask Claude to log the current task or run `/eklavya:quiz`.

</details>

## Memory and search

Start with:

```bash
eklavya memory status
```

| What you see | Next step |
|---|---|
| `capture: off` | Review your [memory settings](/docs/configuration/). If you kept Claude Mem during installation, Eklavya intentionally does not record. |
| Pending evidence but no entries | Run `eklavya memory process` to summarize pending work. |
| `queue:` shows paused jobs | The `paused:` line names the cause: resolve provider login, quota or missing executable, then run `eklavya memory process` to requeue the paused work. It does not resume automatically. |
| `spool drops:` above zero | Evidence did not reach the database. `eklavya memory replay` can recover available evidence from this checkout's Claude Code transcripts. It also backfills work from before installation. |
| Search misses another project's work | Add `--all-projects` to the search. Searches otherwise use the current checkout. |
| Imported entries are `unplaced` | Rerun the import from the source database; use `--map-here` for a project name that cannot be resolved. See [Moving from Claude Mem](/docs/migrating/). |
| Searches miss Japanese or Chinese text | Prefer `retrieval.mode: hybrid`; keyword search struggles with unspaced scripts. Try a filename or identifier as the query. |
| Savings say “unavailable” or show overhead | No confirmed delivered reuse means unavailable. On small histories, recalled observations can cost more tokens than the original evidence. This is reported rather than hidden. |
| Unwanted content was recorded | Ask Claude to delete the affected memory entry with `memory_delete`, then adjust `privacy.exclude_paths`, `privacy.exclude_tools` or `privacy.redact_patterns` to prevent recurrence. |

To switch from Claude Mem, run `eklavya install --memory eklavya` after reviewing
[the migration steps](/docs/migrating/).

<details>
<summary>Recovery from the version 1.24.0 memory-worker loop</summary>

If configuring a memory model created many `claude` or `node` processes:

1. Run `eklavya config set providers.observer null`, then `eklavya memory stop`.
2. Run `eklavya update`. On a version without that command, use
   `npm install -g eklavya@latest && eklavya install`.
3. Check `eklavya memory status`: there should be at most one worker PID. Old
   untracked workers may need to be stopped manually or by restarting.
4. Inspect `eklavya memory backlog`. Use `eklavya memory backlog quarantine --helpers`
   to set aside helper-session noise before restoring the model. Use
   `discard --helpers` only if you want to delete that queued evidence.

</details>

## Commit gate

| Symptom | Check or repair |
|---|---|
| Commit blocked | `/eklavya:gate` shows outstanding concepts. `/eklavya:quiz` starts the required practice; a passing result clears the gate. |
| You did not expect enforcement | Check the effective `quiz.enforced` value. To disable a project's override, run `eklavya config set quiz.enforced false --project`. |
| Enforcement enabled but commits pass | Questions must also be enabled. Doctor reports `quiz.enabled: false` with enforcement. For terminal commits, verify the git hook plus `jq` and `sqlite3`. |
| Git hook never runs | If `core.hooksPath` points to husky or another manager, add the line printed by Eklavya's hook installer to that manager's pre-commit hook. |
| Claude's commit escaped enforcement | Shell aliases, command variables and scripts can bypass the Claude-side check. The [git hook](/docs/commit-gate/#installing-the-git-hook) covers commits at git itself. |
| Every commit says the gate script is missing | Reinstall Eklavya, or remove its git hook using the command printed by uninstall. |

## Claude Desktop and Cowork

| Symptom | Check or repair |
|---|---|
| Questions have no Eklavya header chip | Desktop uses cards. Eklavya questions start with `[Eklavya]` instead. |
| Terminal works but Cowork does not | Cowork needs its own [plugin installation](/docs/installation-options/#claude-desktop-and-cowork). Doctor verifies the Claude Code install only. |
| Cowork asks about code when you are producing documents | Report your Claude Desktop version; Eklavya may not recognize its session entrypoint. Setting a variable in your terminal does not change Desktop's hook environment. |
| Cowork does not block commits | Expected: Cowork does not commit. Enforcement can still ask questions. |
| Nothing works in a managed Cowork installation | Ask the administrator whether local MCP servers are disabled (`isLocalDevMcpEnabled: false`) or a full-VM sandbox prevents access to the local runtime. |

If a repair fails, [open an issue](https://github.com/ProjectAJ14/eklavya/issues)
with the Eklavya version, environment and relevant diagnostic output. Remove
secrets and private project details first.
