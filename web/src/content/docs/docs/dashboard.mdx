```bash
$ eklavya dashboard
Eklavya dashboard on http://127.0.0.1:41729
Reading /Users/you/.eklavya/knowledge.db — press Ctrl+C to stop.
Opening it in your browser…
```

It opens your default browser for you. The command then stays in the foreground
because it *is* the server — Ctrl+C stops it, and `eklavya dashboard &` frees the
terminal if you want it running while you work. On a machine with no browser to
open — a container, a bare SSH session — the attempt fails silently and the URL
above is still what you need.

`/eklavya:progress` fits in twenty lines and answers *what now*. The dashboard is
the long view: nine sections behind a sidebar, each one answering a different
question, with every concept, session, question and remembered observation
reachable in two clicks.

## The sections

Each is a link, so you can bookmark the one you actually use.

| Section | What it answers |
|---|---|
| Overview (`#/overview`) | Am I getting better? Accuracy, mastered, due, current and best streak, thirty days of answers, a year of practice as a calendar heatmap, your weakest five, the last five sessions — plus the two memory summaries below. |
| Concepts (`#/concepts`) | What am I learning? Every concept in your graph, searchable, filterable by state or domain, sortable, 20 to a page. The state filter is part of the address: `#/concepts/due`, `/learning`, `/mastered`, `/unseen`. |
| Review (`#/review`) | What is waiting? Everything due, sorted by how overdue it is; everything else that is scheduled, soonest first, under a fourteen-day forecast chart (`#/review/upcoming`); and the skipped backlog (`#/review/skipped`). |
| Sessions (`#/sessions`) | What happened in that session? One row per session that captured or logged anything, with what it captured, what it remembered, what it logged and what you were asked. |
| Projects (`#/projects`) | How hard is this codebase allowed to get? Per project: accuracy, the level ladder, and the exact runway to the next promotion. |
| Domains (`#/domains`) | Where are the gaps? Coverage per domain, and the tier spread of what you have been asked. |
| Memory (`#/memory`) | What does it remember? The observation timeline, searchable and filterable, 25 to a page. The type filter is part of the address: `#/memory/bugfix`, `#/memory/decision`, `#/memory/untyped`. |
| Reuse (`#/reuse`) | Did reusing memory actually save anything? One row per context injection, with the arithmetic spelled out. |
| Health (`#/health`) | Is capture working, and where did it stop? Heartbeat, queue, stalled jobs and provider state. |

## Opening one thing

Rows are clickable, and the detail pages are where the dashboard stops being a
report and starts being a record.

- **A concept** (`#/concept/<slug>`) shows its score and how much of it is
  decay, its SM-2 state (reps, ease, interval, next review), every grade in
  order as a chart, **every question you were asked on it** — the options, the
  one you picked, and what the tutor told you afterwards — the most recent
  context lines the agent wrote when it logged the concept, and its
  prerequisites, what it
  unlocks and its neighbours, each a link.
- **A session** (`#/session/<id>`) is the whole thread in one place: how much
  evidence it captured, the observations written from that evidence, the concept
  candidates those observations proposed, what the work logged with the context
  line for each concept, what was pulled in for review rather than logged by the
  work, and every question asked in that session with its grade.
- **A domain** (`#/domain/<name>`) lists its concepts, weakest first, with what
  is mastered, learning and not yet asked.
- **An observation** (`#/entry/<id>`) shows the narrative, the facts, the files
  it touched, its tags, which summariser wrote it and how confident that
  summariser was, the concept candidates it proposed, the receipts that ever
  reused it, and — opened one at a time — **the raw evidence it was distilled
  from**, exactly as captured. If it was corrected or deleted, the page says so
  and links the replacement.

## Memory

The timeline shows every observation, including the ones that are no longer
current. A **superseded** row is one a later observation corrected; a
**deleted** row was removed by hand. Both stay in the list, struck through and
labelled, because the point of the page is that you can check the record — and
both are already excluded from search and from what the agent is given.

Filter by type with the chips, by tag with the dropdown, and by date with the
two date fields. The search box matches titles, narrative, facts and file paths.
The project selector in the sidebar narrows the timeline to one repository.

The five numbers along the top are five different things, and the difference
between them is the point:

| Number | What it counts |
|---|---|
| Observations | Live observations — not superseded, not deleted. |
| Evidence | Raw events the hooks captured, and how many of those have been distilled into an observation yet. |
| Indexed | Live observations carrying a vector, which is what semantic search can reach. |
| Reused | Observations that were ever selected for a context injection, and how many of those were part of a *confirmed* delivery. |
| Assessed | Concepts that came out of evidence **and** that you were actually asked a question about. |

The last row is the one that matters most: being remembered is not being
learned. An observation can be captured, indexed, retrieved and handed to the
agent without you ever answering a question about it, and nothing on this page
counts that as understanding.

## Reuse: what `B` and `D` mean

Every time Eklavya injects remembered context, it writes a **receipt**. The
receipt records two numbers, counted with the same estimator on both sides:

- **`B`** — *base*. What the same material would have cost to read from source:
  the files, the diffs and the tool output the observations were distilled from.
- **`D`** — *delivered*. What was actually put into the context window instead.

The percentage is `(B − D) / B`.

:::caution
**It is an estimate of context volume, not a bill.**
Tokens here are estimated at four characters per token, and the figure measures
how much **context volume** was avoided — not money, not your API bill, not
model spend. Eklavya has no way to see what you are charged, and does not claim
to. The estimator's name is printed on the page and on every receipt so you can
see both sides of the subtraction were counted the same way.
:::

A receipt also records its **delivery**:

| Delivery | Meaning |
|---|---|
| `confirmed` | The host confirmed the context reached the model. |
| `unknown` | Eklavya could not tell. |
| `prepared` | The context was assembled but never confirmed as sent. |

**Only `confirmed` receipts contribute to the headline `B`, `D` and percentage.**
The others appear in the ledger, with their own `B` and `D`, and no saving next
to them — an injection that may never have reached the model is not a saving.
If nothing is confirmed, the page says there is no saving to report rather than
printing an optimistic number.

The **detail fetch** column is the honest tail. A session seam usually sends a
short index of observations and only pulls the full text of one when the agent
asks; that later fetch is charged back to the same receipt, so the percentage
falls to what the reuse actually cost instead of keeping the index-only figure.

## Health

Capture, processing, indexing, retrieval and delivery fail in different ways,
and the page keeps them apart so you can tell which one stopped.

- **Last capture** — the newest evidence event. If this is days old while you
  have been working, capture is the problem, not the summariser.
- **Queued / paused / failed** — observation jobs, with the age of the oldest
  one still waiting.
- **Stalled jobs** — grouped by `error_class`: `transient`, `auth`, `quota`,
  `overflow`, `malformed` or `permanent`. `transient` retries itself; `auth` and
  `quota` need you. The error *message* is never shown, because a provider
  message can quote the request that produced it.
- **Dropped** — events the on-disk spool could not keep when the database was
  locked. Anything above zero is evidence that was lost.
- **Providers** — whether an observer or embedding provider is configured at
  all, and which model it names. API keys are read from the environment, never
  stored, and never shown here.

The "captured is not assessed" ladder repeats the six counts from the Memory
page as a bar each, so a number that falls off between two rows shows you where
the pipeline stops.

## Scope, ground and paging

The **project selector** in the sidebar scopes the whole page: pick one and the
tiles, charts, sessions and concept list all narrow to concepts your work in
that repository has touched. The choice is remembered in your browser. Mastery
itself is not per project — a concept you know is a concept you know — so scores
and review dates do not change when you switch.

The **ink / paper** toggle is the same one the site uses, and remembers your
choice. Tables page at 20 rows, the memory timeline at 25, question histories
at 5.

Everything that looks clickable is: the wordmark goes back to the overview, a
row opens its detail page, and a stat tile whose number is a list — due, mastered,
sessions — takes you to that list. Rows are reachable with Tab and open with
Enter.

## What it is, underneath

One static page and three read-only JSON endpoints on loopback — and loopback
is not by itself the protection it sounds like. A web page you happen to have
open can point a hostname it controls at `127.0.0.1` and fetch from a local
server, and the browser's same-origin rule does not stop it, because the page's
origin *is* that hostname. So the dashboard checks that the request was
addressed to loopback **by name** and refuses anything else with a 403. Nothing
here writes, so the risk was never that someone changes a setting; it is that
this page now carries your prompts, your code and your project history.

`/api/state`
ships flat rows — every attempt, every logged context, one row per day, plus the
memory, reuse and health summaries — and the page derives the views, so nothing
on screen is a number the database does not hold.

The one exception is the memory timeline. An observation carries a narrative and
the tool output behind it, so shipping the whole corpus on every load would be
megabytes for a page showing twenty-five rows; it is paged over `/api/memory`
instead, with one observation's full detail and raw evidence at
`/api/memory/entry`. Everything stored is escaped before it reaches the page —
an observation's title is whatever a tool printed, and it is shown as text, never
as markup.

Nothing here writes. The dashboard reads the same
`~/.eklavya/knowledge.db` as everything else, binds to `127.0.0.1`, and serves
to nobody but you. There is no build step, no framework and no network call
except the fonts.

`--port` if 41729 is taken; if the port you asked for is busy the command fails
rather than quietly moving, and with no `--port` at all it falls back to any
free port. `--no-open` skips the browser and just prints the URL.
