Eklavya helps you understand the code Claude writes and remember the decisions behind it. Learning and memory share one local database, but have separate switches: turning questions off does not stop memory capture.

## The three moving parts

| Part | Responsibility |
| --- | --- |
| **Hooks** | React to session events: load context, capture work, prompt a quiz, or check a commit. |
| **MCP server** | A local Node process that exposes tools to Claude. It selects concepts, stores answers, updates review schedules, and searches memory. |
| **Skills and agents** | Instructions that guide Claude's teaching: write questions, assess answers, explain mistakes, and create optional explainer pages. |

Claude calls the server through the Model Context Protocol (MCP). Hooks open the same SQLite database directly; they do not send their reads and writes through the MCP server. The [dashboard](/docs/dashboard/) and [CLI](/docs/cli/) also use this local store.

Questions wait until the session changes code: Claude edits a file with its edit tools, in this checkout or a sibling worktree, or the git working tree the session started in differs from how it was at the start. Only work logged in the last hour is asked about, newest first. Reading and research sessions are not quizzed ([`quiz.only_on_changes`](/docs/configuration/)). Once that happens, checkpoints ask one question while work continues, with a four-minute minimum gap. Mid-task and end-of-task questions share a four-attempt session budget. `cadence: "end"` moves automatic questions to the end; an enforced gate can require further attempts to pass. See [quiz settings](/docs/dials/) and [grading](/docs/grading-engine/) for the exceptions and scoring rules.

Delegated agents can log concepts, but questions return to the main conversation. This keeps a quiz out of a background transcript you cannot answer. The [first-session walkthrough](/docs/first-session/) shows what you see as a developer.

Raw events, observations, and answers live in `~/.eklavya/knowledge.db` by default. Recall is limited to the current project unless you enable cross-project retrieval. See [memory](/docs/memory/) for capture controls, search, collections, code indexing, and optional integrations, or [your data](/docs/your-data/) for storage and backup.

Local storage does not mean recalled text stays outside Claude: it becomes part of the conversation. Optional observers, notifications, and sync may also move data through services you configure. Installation and update checks contact the package registry. The daily [usage ping](/docs/usage-analytics/) sends anonymous counts to Google Analytics unless you turn it off.

## Runtime requirements

Eklavya requires **Node.js 22 or newer**. Its SQLite driver, `better-sqlite3`, includes native code, so installation also needs a compatible binary or the platform's build tools. Start with the [installation guide](/docs/installing/); use [troubleshooting](/docs/troubleshooting/) if the driver fails to load.

Git is optional for ordinary learning and memory. Without a repository, difficulty uses a shared fallback scope and there is no commit to gate. The optional terminal [Git gate](/docs/commit-gate/) additionally needs a POSIX shell, `jq`, and the `sqlite3` command-line tool; the Claude Code hooks do not.
