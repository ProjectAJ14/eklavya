Use the CLI for installation, settings, diagnostics and memory outside a Claude Code conversation. Run a command with `npx eklavya`, or install it on your `PATH`:

```bash
npm install -g eklavya
eklavya doctor
```

## Installation and maintenance

| Command | Purpose and options |
| --- | --- |
| `eklavya install` | Installs the runtime, Claude Code plugin, database and two chat skills. The first install walks through your settings; later runs preserve them. `--settings` opens the choices again. `--memory eklavya` or `--memory claude-mem` chooses the recorder when Claude Mem is present. See [Installing](/docs/installing/) and [Migration](/docs/migrating/). |
| `eklavya update` | Checks npm and installs a newer release, then refreshes the plugin registration. Runs the normal background update in the foreground so errors are visible. Never downgrades. |
| `eklavya uninstall [--purge]` | Removes the installation and keeps your history unless `--purge` is passed. Reports any remaining project installation or git hook. See [Uninstalling](/docs/installing/#uninstalling). |
| `eklavya doctor` | Checks installation and memory health, reports repairs and applies concept packs. See [diagnostics below](#what-doctor-looks-like). |
| `eklavya serve` | Runs the MCP server over standard input/output. Claude Code starts this automatically. |
| `eklavya db-path` | Prints the active database path. |
| `eklavya export-rules [--out <file>]` | Exports the complete tutor text as a Markdown rules file, or prints it without `--out`. This exports instructions only; it does not install another editor's hooks or the automatic learning loop. |

`install --auto` is used internally by the updater: it skips the runtime installation step and interactive questions. Normal installs repair missing files without resetting history.

## Settings and browsing

| Command | Purpose and options |
| --- | --- |
| `eklavya config get` | Prints effective settings and global/project file paths. Warns about malformed files or global-only settings ignored in a project file. |
| `eklavya config set <key> <value>` | Sets one key globally. Add `--project` (legacy alias `--repo`) for this codebase; add `--topic <topic>` when setting `focus learn`. |
| `eklavya dashboard [--port <n>] [--no-open]` | Starts the [local dashboard](/docs/dashboard/). `--no-open` prints the URL without opening a browser. |
| `eklavya statusline [--no-color]` | Prints one line for a terminal status bar. See [below](#eklavya-statusline). |
| `eklavya artifacts <subcommand>` | Creates, lists and opens saved pages. See [below](#eklavya-artifacts). |

```bash
eklavya config set cadence end --project
eklavya config set focus learn --topic caching
eklavya config set memory.capture minimal
```

Settings are backed up to `config.json.eklavya-bak` before a change. Unknown keys, malformed files, `focus learn` without a topic, and `--project` outside a git repository are rejected with a repair message. See [Configuration](/docs/configuration/) for every key and default.

### `eklavya memory`

Run project-specific commands from inside the checkout. Memory maintenance does not change quiz attempts, mastery or gates.

| Subcommand | Purpose and options |
| --- | --- |
| `status` | Shows entries, pending evidence, queue status, provider configuration, worker processes and heartbeat, imported/unplaced history, dropped events and estimated reuse. Start here when memory seems empty. |
| `search <query>` | Finds titles and IDs. Options: `--mode keyword\|semantic\|hybrid`, `--limit <n>`, `--all-projects`. |
| `timeline` | Lists recent entries, newest first. Options: `--limit <n>`, `--since <iso date>`. |
| `show <id>` | Reads one entry and its raw evidence. |
| `replay [--limit <n>]` | Backfills this checkout's Claude Code transcripts, including sessions before installation or missed by hooks. |
| `process [--max <n>] [--no-resume]` | Processes queued observations now. Normally resumes paused jobs; `--no-resume` leaves them paused. |
| `stop` | Cancels the recorded worker and its model call; unfinished work returns to the queue. Future session activity can start a worker again. |
| `backlog` | Lists unfinished jobs by project and status, plus Eklavya observer helper sessions in any state, marked as such. |
| `backlog quarantine\|discard\|restore` | Changes selected jobs. Requires `--helpers`, `--project <key>`, `--session <id>` or `--batch <id>`. Quarantine preserves jobs without processing; restore re-enables them; discard deletes unfinished jobs and their raw evidence; with `--helpers` it also deletes finished helper sessions and the memories they produced. |
| `prune` | Applies this project's `memory.retention_days` now, removing old summarised evidence, finished jobs and reuse receipts. Keeps observations; does nothing when retention is unset. |
| `import <source.db>` | Imports Claude Mem history. Options are [below](#importing-claude-mem-history). |
| `export <file> [--force]` | Writes a private, versioned JSON memory backup. Refuses to replace an existing file without `--force`. |
| `restore <file>` | Adds missing memory from an export and rebuilds its search data. Repeating the restore adds no duplicates. |
| `sync push\|pull\|status [--target <dir>]` | Exchanges memory entries, tags and deletions through a shared folder. Requires `sync.enabled` and a target. Learning history, raw evidence and receipts do not sync. |

If processing paused because of login, quota or a missing `claude` command, fix that problem and run `eklavya memory process`. Automatic seams leave paused jobs alone. Only one worker runs at a time; it handles up to four batches before handing remaining ready jobs to a fresh worker. To keep model processing off, clear `providers.observer`.

```bash
eklavya memory search "refresh cookie"
eklavya memory status
eklavya memory export ~/eklavya-memory-backup.json
```

A memory export contains entries, tags, evidence and its links, and reuse receipts. **It is not a backup of quiz history or a full database rollback.** Restore is additive: it does not remove existing entries or undo later edits. For a complete backup, see [Your data](/docs/your-data/#backups-of-your-own-files). A restore from an unsupported newer format stops with a version error.

#### Importing Claude Mem history

```bash
eklavya memory import ~/.claude-mem/claude-mem.db --dry-run
```

| Option | Effect |
| --- | --- |
| `--dry-run` | Reads the source without writing; reports schema, row counts, project names and field mapping, including dropped or unknown fields. |
| `--verify` | Checks every source row by ID and reports project placement. Writes nothing; exits 1 if anything is missing. |
| `--resume` | Reuses the snapshot from an interrupted import. |
| `--map <name>=<path>` | Assigns a named source project to a checkout. Overrides transcript-based mapping. |
| `--map-here <name>` | Assigns it to the checkout you are in. |

Imports preserve original dates, do not duplicate rows, and never count imported concepts as assessed knowledge. Re-running with a better map moves unplaced rows to their checkout. Unplaced history remains searchable with `--all-projects`. Unsupported newer source schemas are rejected. See [Moving from Claude Mem](/docs/migrating/) for the installer flow and rollback.

### `eklavya artifacts`

| Subcommand | Purpose and options |
| --- | --- |
| `new <title>` | Starts an HTML page from the template and prints its path. Options: `--description <text>`, `--kind artifact\|explainer` (default `artifact`), `--concept <slug>`, `--open`. |
| `list [--json] [--here]` | Lists pages newest first. `--here` selects this project; `--json` includes the IDs used by the dashboard. |
| `open <path\|id>` | Opens a page by path or an ID from `list --json`. |

Files live under `~/.eklavya/artifacts/<project>/`, named with the local date and title. Repeated titles receive a suffix instead of overwriting a file. A worktree uses its main checkout's folder; outside git, the current directory identifies the project. See [the artifacts skill](/docs/commands/#the-artifacts-skill) to have Claude write the content.

### `eklavya statusline`

Prints your focus, cadence and current level, with `enforced` when the commit gate is enabled:

```text
[EKLAVYA concept · interleaved · easy]
```

The installer adds this only if Claude Code's status-line slot is empty. To configure it yourself:

```json title="~/.claude/settings.json"
{
  "statusLine": {
    "type": "command",
    "command": "eklavya statusline"
  }
}
```

If you already have a status-line script, append the output of `eklavya statusline` there. It exits successfully with one line or no output. Uninstall preserves a composed status line.

It stays silent when questions are disabled, `quiet` is true, or the session is silenced. Use `--no-color` or `NO_COLOR` for plain text. It shows the project level rather than an individual question's tier; past tiers are in the dashboard. Claude Desktop has no terminal status bar, so its questions use an `[Eklavya]` signature instead.

### What `doctor` looks like

Run this when Eklavya is unexpectedly quiet:

```bash
eklavya doctor
```

The report checks the runtime, SQLite driver, plugin registration, both chat skills, update status, version alignment, configuration, database, concept packs, project level, memory queue and gate dependencies. Marks distinguish healthy (`▣`), warning (`!`), skipped (`◌`) and failed (`▤`) checks, including without colour.

| Finding | Repair |
| --- | --- |
| Missing runtime, incompatible SQLite driver, missing registration or skill | Run `eklavya install`. A conflicting user-owned skill must first be moved by you. |
| Failed automatic update | Run `eklavya update`; inspect `~/.eklavya/update.log`. |
| Plugin/runtime versions differ | A behind runtime normally catches up next session; an older plugin needs updating through Claude Code's plugin controls. |
| Malformed configuration | Fix the named file; the installer will not overwrite it. |
| Broken concept pack | Fix that pack; the rest still loads. |
| Installed terminal gate lacks `jq` or `sqlite3` | Install the missing dependency. Until then, that gate lets commits through. |
| Paused memory queue | Fix the reported login, quota or command problem, then run `eklavya memory process`. |

`doctor` exits nonzero for failed checks and names the repair. A broken pack is reported without failing the run. It also opens/initialises the database and applies packs, so it is a diagnostic command with those limited writes. Hooks fail open to protect your session; this report distinguishes a quiet session from a broken installation.
