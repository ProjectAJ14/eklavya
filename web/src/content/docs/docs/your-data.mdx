Everything Eklavya knows about you is in one directory. There is no account and no telemetry, and with the default configuration nothing about your code leaves the machine.

Two things can change that, and neither is on unless you turn it on: `providers.observer` sends batches of captured work to a model API so it can write richer observations, and `notifications` and `sync` send wrap-ups or memory entries to somewhere you name. [Configuration](/docs/configuration/) has all three, and each one says what leaves.

| Path | What it holds |
| --- | --- |
| `~/.eklavya/knowledge.db` | SQLite, WAL mode. The learning half: concepts and their prerequisite edges, your mastery per concept, every attempt, what each session logged, the gates, each project's level, and the pacing state that stops it asking twice in a row. The memory half, in the same file: the raw evidence of what each session did, the observations distilled from it, the search index and its vectors, the reuse receipts, saved collections, and the concept candidates evidence proposed. |
| `~/.eklavya/spool/events.jsonl` | Evidence captured while the database was unreachable, waiting to be replayed. Sanitised before it is written, and emptied on the next healthy session. Usually absent. |
| `~/.eklavya/config.json` | Your global settings. |
| `<repo>/.eklavya.json` | Per-project settings, checked into the repository if you want them shared. |
| `~/.eklavya/packs/*.json` | Your own [concept packs](/docs/packs/) — extra domains Eklavya can quiz on. |
| `<repo>/.eklavya/packs/*.json` | The repository's packs, checked in and applied for everyone working in it. |

### Looking inside

```bash
eklavya db-path
sqlite3 ~/.eklavya/knowledge.db '.tables'
sqlite3 ~/.eklavya/knowledge.db 'select domain, count(*) from concepts group by domain'
sqlite3 ~/.eklavya/knowledge.db \
  'select c.slug, m.score, m.next_review from mastery m join concepts c on c.id = m.concept_id'
```

### Experimenting safely

Two environment variables redirect everything, so you can try settings without touching your real history:

```text
export EKLAVYA_HOME=/tmp/eklavya-test   # whole directory
export EKLAVYA_DB=/tmp/test.db          # just the database
```

A third changes wording rather than data. Eklavya works out whether it is in a
Claude Code session or a Cowork one from the entrypoint the app sets, and words
its questions accordingly — code and diffs in the first, the work you produced
in the second. `EKLAVYA_SURFACE` pins it:

```text
export EKLAVYA_SURFACE=cowork   # or: code
```

This one only reaches a process that inherits your shell — the `eklavya` CLI, or
Claude Code started from a terminal. It does **not** reach a Cowork session:
Claude Desktop composes the environment for the hooks and the server itself, and
the shell you can reach there belongs to the sandbox VM, which they are not
started from. So it is a testing and CLI knob rather than a fix for a
misdetected Cowork session — if you ever hit one of those, it is a bug worth
[reporting](https://github.com/ProjectAJ14/eklavya/issues) with your app version.

### The two halves are separable

They share a file, and they are not the same data. Learning history — your
attempts, your mastery, your review schedule — cannot be rebuilt from anything;
if you lose it, it is gone. Memory can be: the evidence is a record of work
that also exists in your repository's history, and the search index and vectors
are derived and rebuildable from the entries.

That asymmetry is why a backup matters more for the learning half, and why
`memory.retention_days` exists to age out raw evidence while keeping the
observations built from it.

To stop one without the other:

```bash
eklavya config set mode off               # no questions; history keeps recording
eklavya config set memory.enabled false   # no history; questions keep coming
```

### Deleting it

```text
rm -rf ~/.eklavya
```

That is the whole uninstall of your data. Eklavya forgets you entirely.

:::caution
**Never commit a learner's database.** `knowledge.db` and anything under `~/.eklavya/` is personal. The two Eklavya files meant to be checked in are `.eklavya.json` and a repository's own `.eklavya/packs/` — neither holds anything about you.
:::
