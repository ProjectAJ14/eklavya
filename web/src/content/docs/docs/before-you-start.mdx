One thing needs to be on your machine.

| Requirement | Check it with | Why Eklavya needs it |
| --- | --- | --- |
| **Node 22 or newer** | `node --version` | Runs everything: the MCP server, the `eklavya` command, and all four hooks. |

That is the whole list, on macOS, Linux and Windows alike. Earlier versions of Eklavya also needed `jq` and the `sqlite3` command line tool, because the hooks were shell scripts. They are Node now, so there is nothing else to install and nothing to go missing.

### Why Node 22 specifically

Eklavya stores your knowledge graph in SQLite, through a driver called `better-sqlite3`. That driver is native code, and it ships ready-compiled binaries for Node 22 and newer. On Node 20 or older there is no ready-made binary for your platform, so `npm` falls back to compiling one, which needs a full C++ toolchain — Xcode command line tools on macOS, Visual Studio Build Tools on Windows.

Rather than let you find that out halfway through, `npx eklavya install` checks your Node version first and stops with instructions if it is too old.

```text title="macOS"
brew install node
```

```text title="Windows"
winget install OpenJS.NodeJS.LTS
```

```text title="Linux"
# with nvm
nvm install 22 && nvm use 22
```

:::note
**One exception, for one optional feature.** The git `pre-commit` gate — which enforces the quiz for commits made outside Claude Code, in enforced mode only — is a POSIX shell script, because a git hook should not pay Node's startup cost on every commit. It needs `jq` and the `sqlite3` command line tool, and it fails open with a warning when they are absent. Nothing else in Eklavya does. Install them with `brew install jq sqlite` or `sudo apt-get install -y jq sqlite3` if you want that gate.
:::

:::note
**git is optional.** Without it Eklavya still runs, but two things change: your difficulty level is tracked in one shared bucket instead of per project, and the commit gate has nothing to attach to. Everything else works.
:::
