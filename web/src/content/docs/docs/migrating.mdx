Claude Mem and Eklavya's memory do the same job. Both record every session and
recall it at the next one. Leave both installed and every session is captured
twice and recalled twice. You only need one, and switching takes one command:

```bash
eklavya install
```

If it finds Claude Mem (its plugin, or `~/.claude-mem/claude-mem.db`), it asks
which one should record:

```text
Claude Mem is installed. Both record every session, so only one should.
  1  Eklavya     import its history, then uninstall Claude Mem  (recommended)
  2  Claude Mem  keep it; Eklavya turns its memory off, quizzes stay on

[1/2]
```

To skip the question, pass `--memory eklavya` or `--memory claude-mem`. If
there is no terminal to ask, the installer picks Claude Mem, because that
choice changes nothing of Claude Mem's.

## Choosing Eklavya

The installer does four things, in this order:

1. **Imports the history.** It opens `claude-mem.db` read-only, snapshots it,
   and imports observations, session summaries, prompts and tool uses. Each
   one keeps its **original** timestamp.
2. **Files each project under its checkout.** Claude Mem names a project with a
   bare string, like `storefront`. Eklavya keys a project by the checkout's
   path, because two repositories can share a folder name and must never share
   a history. Every Claude Mem session carries its Claude Code session id, and
   Claude Code's transcript for that session records where it ran. So the
   installer reads each checkout from your transcripts instead of guessing from
   the name. That also works for a checkout you have moved since.
3. **Uninstalls the Claude Mem plugin** with `claude plugin uninstall`. If the
   `claude` command is not on your `PATH`, it switches the plugin off in
   `~/.claude/settings.json` instead.
4. **Moves `~/.claude-mem` to `~/.claude-mem.retired`.** A move, not a delete:
   it is your rollback. Delete it once you are happy.

If the import fails, the installer stops before step 3. Claude Mem stays
installed and Eklavya's memory is switched off, so you still have exactly one
recorder. The message says why the import failed.

What arrives:

- observations and session summaries become memory entries;
- prompts and tool uses become evidence, linked to the entry they belong to, so
  the drill-down from an imported entry works as it does for a live one;
- concepts Claude Mem had attached become **candidates**. An import never
  grants mastery, records an attempt or opens a gate. History is not proof
  that you understand something.

What does not arrive: device identities and sync state from other machines,
Claude Mem's live worker queue, notifications it already sent, and opaque
metadata. That is Claude Mem's runtime state, not your history.

### Projects it could not place

The install report ends with a count of unmatched projects. A project is
unmatched when none of its sessions ran in a checkout that still exists, or
when it was never a real checkout (a home directory, a scratch folder). Its
entries are still imported and still searchable, but only with
`--all-projects`. To place one, run this from inside its checkout:

```bash
cd ~/work/storefront
eklavya memory import ~/.claude-mem.retired/claude-mem.db --map-here storefront
```

`--map <name>=<path>` does the same for a checkout you are not standing in. A
second import never duplicates anything it already brought in.

## Choosing Claude Mem

Eklavya sets `memory.enabled` to `false` in `~/.eklavya/config.json`, and that
is the only change. Questions, levels and the commit gate work as before.
Nothing of Claude Mem's is touched, and later installs do not ask again.

To switch later, run `eklavya install --memory eklavya`. It imports, switches
Eklavya's memory back on, and retires Claude Mem as above.

## Going back

Rename `~/.claude-mem.retired` back to `~/.claude-mem`, reinstall the Claude
Mem plugin, and run `eklavya config set memory.enabled false`. Anything Eklavya
recorded in the meantime stays in its own database, and
`eklavya memory export <file>` / `eklavya memory restore <file>` back it up and
bring it back.

## Doing it by hand

`eklavya memory import` is the same importer without the install around it. Run
a dry run first. It writes nothing, and it prints the schema version, the row
counts per project, and a field-by-field report of what maps where and what is
dropped:

```bash
eklavya memory import ~/.claude-mem/claude-mem.db --dry-run
```

An interrupted run continues with `--resume`. If the source is newer than the
importer understands, it stops and names both versions rather than guess at a
schema it has never read. Every flag is on [the CLI page](/docs/cli/).
