## Does it work in Claude Desktop?

The **Code** tab uses your Claude Code installation. **Cowork** needs a separate
plugin install. Ordinary **chat** does not load Eklavya. See
[Installation options](/docs/installation-options/#claude-desktop-and-cowork).

## Is Cowork different?

Questions refer to the documents and analysis you produce. The commit gate has
nothing to block, and delegated subagents are not instructed to log concepts.
Questions carry `[Eklavya]` in the card because there is no terminal header or
status bar.

## Does anything leave my machine?

Eklavya stores data locally, and its default memory summarizer and search index
run locally. It has no separate account. It does send anonymous daily usage
counts, never paths, names or text; `eklavya telemetry off` stops them, and
[Usage analytics](/docs/usage-analytics/) lists every field. **Recalled memories are
provided to Claude as session context**, alongside the work you already do
with Claude.

Automatic updates contact npm without sending your learning or memory data;
`auto_update: false` disables those checks. The local dashboard keeps running in
the background on `127.0.0.1` only and makes no outbound requests;
`dashboard_autostart: false` stops it being started. Saved explainer pages can request Google Fonts, with system
font fallbacks when offline.

Optional providers send captured work through Claude Code to a configured
model. Notifications can send wrap-ups to a destination you choose, and sync
writes memory to a directory you choose. None is enabled by default. See
[Memory](/docs/memory/) and [Configuration](/docs/configuration/) before enabling
them.

## Does it remember my code?

It records prompts, Claude's final message for each turn and tool-call
evidence, including arguments, paths, errors and an excerpt of each result,
then turns them into observations. File reads and edits keep no result, so
your repository is not stored as a second copy, but arguments and command
output can contain code.
Privacy filters exclude common secret paths and redact recognized secret
patterns; review [what memory captures](/docs/memory/) before working with
sensitive material.

## Will it slow down my work?

Questions interrupt briefly; local hooks read the database directly. Change
the cadence or question budget if the default pace is too frequent. A
configured memory model also uses your Claude subscription. See
[The dials](/docs/dials/).

## Can I skip a question?

Yes. A skip is recorded as a decline with grade 0 and excluded from accuracy.
A clean decline without tutor feedback is not retried by the gate; a decline
with an explanation can return. With enforcement enabled, skipping does not
remove the requirement to pass enough concepts before committing.

## Can I pause questions for one session?

Say **“turn Eklavya off for this session.”** It hides questions, checkpoints,
the banner and status bar without changing saved settings. Memory continues.
The installed git commit gate still follows the project's enforcement setting.

For persistent changes, set `quiz.enabled` or `memory.enabled` separately.
There is no session-only memory switch.

## Why did it ask about something I already know?

The concept may not yet meet the mastery threshold, your last answer on it may
have been declined, blank or wrong, or today's work may have touched it while its
spaced review was due. A concept whose last answer was right is not brought
back from an earlier session. Questions should vary as you progress through the tiers. See
[Levels and tiers](/docs/levels-and-tiers/).

## Can my team share settings?

Each developer keeps personal settings under `~/.eklavya/`, including
project-specific overrides. Share a [concept pack](/docs/packs/) in the repository
to teach the same project concepts without imposing one learner's preferences
on everyone. Legacy `.eklavya.json` files are migrated out of the checkout;
unsafe repository-supplied provider and notification settings are not trusted.

## Can two Claude Code sessions share one quiz?

Yes. Give both sessions the same `EKLAVYA_SESSION_ID` to use one for building
and one for tutoring. Follow the
[parallel tutoring guide](https://github.com/ProjectAJ14/eklavya/blob/main/docs/parallel-tutoring.md).

## I work in two repositories at once. Will they mix?

No. In Claude Code each session's tools use the session ID the host gives
them, so two windows stay separate even in the same checkout or when one edits
a sibling worktree. Hosts that do not provide that ID fall back to a pointer per
checkout, which two sessions in one checkout share. The database itself is
shared across projects.

## How do I upgrade?

Updates run automatically. Use `eklavya update` to update now, then start a new
session. See [Updates and removal](/docs/updates/).

## How do I uninstall?

Run `npx eklavya uninstall` to remove the Claude Code plugin and user skills
while keeping history. Git hooks, project-scoped plugin installs and Cowork
may need separate removal. Follow the
[uninstall guide](/docs/updates/#uninstalling) for those steps or to delete data.

## Still stuck?

Start with [Troubleshooting](/docs/troubleshooting/). If the tool and the manual
disagree, [report the discrepancy](https://github.com/ProjectAJ14/eklavya/issues)
with the command, expected result and actual result. Do not include private
project data or secrets.
