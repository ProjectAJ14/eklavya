Answers update three things: your understanding of a concept, when it returns for review, and your project's progress toward harder questions. An enforced session also counts eligible passes toward its [commit gate](/docs/commit-gate/).

### Concepts and the graph

A **concept** is an idea identified by a lowercase hyphenated slug, with a domain, tier and optional prerequisite relationships. Built-in domains are `web-auth`, `react`, `node-backend` and `git`. [Concept packs](/docs/packs/) and the agent can extend the graph; new agent-created concepts are capped by `max_new_concepts_per_session` (eight by default).

The planner orders prerequisites before dependent concepts and reports missing foundations. It selects a question tier within your project's [level](/docs/levels-and-tiers/).

### Grading: the 0–5 scale

| Grade | Meaning |
| --- | --- |
| `0` | No answer, recorded separately as “I don't know” or a decline. |
| `1–2` | Incorrect. |
| `3` | Correct with difficulty; the minimum passing grade. |
| `4` | Correct. |
| `5` | Correct with an explanation of why. |

A multiple-choice selection is capped at **4**. A written explanation through “Other” can be assessed beyond recognition alone. Declining a question is distinct from not knowing: a decline is dropped without teaching, while “I don't know” leads to an explanation and can support a later follow-up. Declines do not count against promotion accuracy.

With [`explain_on_wrong`](/docs/configuration/#every-key) enabled, wrong or unknown answers also start a background explainer page. The verdict arrives immediately; the quiz does not wait for the page. Skips and declines do not create one.

### Why the questions are multiple choice

Questions offer four options so you can respond while working. Exactly one option should answer the question; the other three are meant to be believable but wrong. The plan assigns the correct answer's position to avoid always putting it first. “Other” lets you say you do not know or give an explanation in your own words.

If another option also answers the question, pick it or say why through “Other”. The tutor grades a defensible answer as correct and says the question had two right answers, so a flawed question does not lower your mastery.

### Scheduling: SM-2

SM-2 is a spaced-repetition method: passing a review increases the delay before the concept returns.

| State | Rule |
| --- | --- |
| First passing recall | Review in one day. |
| Second consecutive passing recall | Review in six days. |
| Later passing recalls | Multiply the previous interval by the ease factor, capped at 3,650 days. |
| Failed recall | Reset consecutive repetitions and review in one day. |
| Ease factor | Starts at 2.5, adjusts after each grade, never below 1.3. |
| Mastery | Score at least 0.7 and at least two consecutive passing repetitions. |

The score is a recency-weighted average of the last five grades, normalised to 0–1; each newer grade has weight 0.6. Two clean grade-4 answers can establish mastery, while one cannot.

For overdue concepts, the displayed score decreases by **0.05 per complete week**, stopping at 0.3 without raising a score already below that floor. This is calculated when reading the record, not written over your history.

### How repetition is reduced

Mastered concepts normally return only when review is due. The planner supplies recent question history so Claude can choose a new angle, and a concept answered in the current session is ordinarily removed from that session's plan.

An unmet enforced gate takes priority: it can ask about mastered work concepts and retry a concept you did not know after teaching it. A retry uses a different question at a lower tier, within the project's band. If automatic questions have used the session budget, `/eklavya:quiz` can request another round of eligible questions. Repeated question text is flagged when an answer is recorded; the answer is still saved, and wording alone cannot guarantee a new angle.

### Where each hook fits

| Event | Responsibility |
| --- | --- |
| `SessionStart` | Load the learner profile and project memory, initialise the session and give logging instructions. |
| `UserPromptSubmit` | Capture your prompt, recall relevant memory and occasionally remind the agent to log concepts when it has not. |
| `SubagentStart` | Give delegated agents the logging instruction; they contribute to your session without quizzing you. |
| `PostToolUse` | Capture tool activity; eligible concept-logging and work calls can trigger a checkpoint question. |
| `Stop` | Process memory and offer the remaining learning work, respecting cadence, spacing and session limits. |
| `PreToolUse` | Under enforcement, block recognised `git commit` commands until the gate passes. |

Hook failures do not break the coding session. [How it works](/docs/how-it-works/) shows the full sequence; [Configuration](/docs/configuration/) lists the limits.
